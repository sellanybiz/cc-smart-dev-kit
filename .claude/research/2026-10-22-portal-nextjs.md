# The portal in Next.js: static export under the strict policy (D49)

Date: 2026-10-22
Status: the recommendation is taken (Pages Router, `next build --webpack`, static export); the owner decides the style-attribute question

**Probe.** Next 16.4.2 (Turbopack default; `--webpack` opt-out), React 19.3.0, Tailwind 4.3.3, shadcn 4.22.1, tweakcn **caffeine** theme, `dashboard-01` block (Recharts 3.8.0, TanStack Table 9.3.1, dnd-kit, vaul), zod 4.6.7, Bun 1.4.3, Node 26.11.1, system Chrome driven by Playwright 1.64.1. Paths: `~/.claude/jobs/0927c5dd/tmp/next-probe/{app-router,pages-router,probe,sse}`; strict-CSP server `probe/server.ts`, drivers `probe/test.mjs`, `probe/dashboard-test.mjs`, `probe/dash-interact.mjs`. Theme confirmed as a `registry:style` of CSS variables only: no `files`, no dependencies, no `@font-face`/`url(...)`, system font stacks, `--radius: 0.5rem`.

**A. Static export, sourced.** App Router: server components run at build; Route Handlers work only as static GET with `dynamic = "force-static"`; dynamic routes need `generateStaticParams`; `next/image` needs a custom loader or `images.unoptimized`; proxy/middleware, `cookies()`, `headers()`, redirects, rewrites, server actions, ISR, draft mode and intercepting routes are unsupported (https://nextjs.org/docs/app/guides/static-exports). Pages Router: `getStaticProps`/`getStaticPaths`, client fetching, CSS Modules and dynamic imports work; API routes, `getServerSideProps`, rewrites/redirects/headers, ISR, `fallback: true|"blocking"` and i18n routing do not (https://nextjs.org/docs/pages/guides/static-exports). Both emit one HTML file per route plus `_next/static`; `trailingSlash: true` emits `route/index.html` (https://nextjs.org/docs/app/api-reference/config/next-config-js/trailingSlash). For a client-heavy ~8-page portal served from a folder, **Pages Router is the better fit** because its webpack export has no executable inline script (proved in B); App Router adds RSC payload scripts and `.txt` payload fetches but works.

**B. CSP, proved.** App Router export emits 8 inline scripts on a simple page (10 on the dashboard): a Turbopack bootstrap `<script id="_R_">`, `(self.__next_f=…).push([0])`, and 4-6 `self.__next_f.push([1,"…"])` RSC-payload scripts. Pages Router + Turbopack still emits 2 executable Turbopack bootstrap scripts; **Pages Router + `next build --webpack` emits exactly one inline script, `__NEXT_DATA__` with `type="application/json"` — data, not executed.** With no hashes, 8 App Router scripts were refused and hydration died (dark-mode toggle did nothing; 15 CSP errors). With build-time sha256 hashes, `script-src 'self' 'sha256-…'` worked: 12 unique hashes for the 8-page app, 41 for the 10-page dashboard build; hydration and every interaction ran (tabs, dialog, dropdown, popover, tooltip, select, switch, toasts, client-side route change). Pages Router + webpack ran under plain `script-src 'self'` with zero script violations, including client navigation. Nonces are impossible: Next's own guide says nonces require dynamic rendering because Next injects them at render time; static pages have no request headers (https://nextjs.org/docs/app/guides/content-security-policy). Its experimental SRI covers external chunk integrity, not inline scripts. Community confirmations: https://github.com/vercel/next.js/discussions/54152 and https://github.com/vercel/next.js/discussions/81703.

**C. Styles.** `style-src 'self'` refuses both `<style>` and `style="…"` attributes (https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/style-src). The caffeine/shadcn export has 6 SSR style attributes (sidebar `--sidebar-width`, Tabs `outline:none`/`animation-duration:0s`, Select `pointer-events:none`, Radix's visually-hidden select and switch inputs) and the dashboard 30 (plus ChartContainer's chart-color `<style>`). Fixes proved:
- Sidebar: move `--sidebar-width`/`--sidebar-width-icon` to `:root` and drop the component's style prop — sidebar 0px became 256px.
- **Recharts is a real break**: ResponsiveContainer and `RechartsWrapper` set `width:100%;height:100%;min-width:0`, `width:0;height:0`, `position:relative;cursor:default;width:320px;height:200px` as inline styles. Blocked, the container measured 0px and no SVG rendered. Adding `.recharts-responsive-container{width:100%!important;height:100%!important}` and `.recharts-wrapper{position:relative}` made it render at 1080×250. Client-only rendering or `'unsafe-hashes'` also fix it.
- **Radix/floating-ui positioning is fine**: popper wrapper got `position:fixed; transform:matrix(...)` through the CSSOM; popover, tooltip, dropdown and select all positioned correctly. dnd-kit is fine: during a row drag, `transform: translate3d(...)` appeared via React's style prop/CSSOM, `data-dragging="true"`, and **0 new CSP violations**. MDN confirms individual `element.style.x` writes are not blocked (same style-src page).
- Sonner injects a 14.9KB `<style>`; importing `sonner/dist/styles.css` gave a fixed 356px bottom-right toaster despite the blocked injection. react-remove-scroll and Radix Select also inject `<style>` (scroll lock, scrollbar); repeat those rules in globals.
- **zod** (used by the dashboard data table) calls `new Function("")` to detect eval: one `script-src` violation per load. It is caught and harmless, but removing zod from the client (plain TS types; validate on the Bun server) made the violation disappear (proved). Known upstream: https://github.com/colinhacks/zod/issues/5789.
- A zero-error policy was proved on the simple page: `style-src 'self' 'sha256-…'` for the 3 library style elements plus the empty style, and `style-src-attr 'unsafe-hashes' 'sha256-…'` for the 6 static attribute values — 0 console errors, everything working. Without `'unsafe-hashes'`, the dashboard logs 35 harmless style violations (30 attr, 5 element) but renders correctly after the CSS fallbacks.

**D. Size/paths.** App Router hello 20 files/676K; Pages Router hello 15 files/440K (Turbopack), 11 files/524K (webpack). App Router + shadcn: 26 files/1.1M; 8 pages 61 files/1.4M. Pages Router + shadcn 8 pages: 924K/27 files. App Router + dashboard-01 (10 pages): 68 files/2.3M (JS 1.5M, CSS 120K). Pages Router + dashboard-01: 32 files/1.7M (JS 1.1M, CSS 116K). `basePath` is build-time and inlined; GitHub Pages templates use it with `output: "export"` (https://nextjs.org/docs/app/api-reference/config/next-config-js/basePath, https://github.com/gregrickaby/nextjs-github-pages). `assetPrefix` rewrites only `_next/static` URLs and is meant for a CDN (https://nextjs.org/docs/app/api-reference/config/next-config-js/assetPrefix); unnecessary locally. `distDir` names the output folder.

**E. Bun.** `bun --bun next build` succeeded and produced the same export at 16.4.2/Bun 1.4.3. Known failures exist at other pairings: Next 16.3 + Bun 1.3.12 (https://community.vercel.com/t/next-js-16-3-bun-runtime-1-3-12-build-failure-on-vercel-while-bun-1-3-14-works-locally/47139) and Bun + Turbopack external modules (https://github.com/vercel/next.js/issues/86866). Pin Bun and prove the build in CI; Next under Node for build only is the fallback.

**F. Data/SSE.** Proved in Chrome against the portal's real header rules: same-origin `EventSource` sends `Sec-Fetch-Site: same-origin`, `Sec-Fetch-Mode: cors`, the session cookie, and **no `Origin`**; a same-origin POST adds `Origin` and a custom `x-ccsdk-csrf` header. Both pass `guard.ts`. EventSource cannot set headers, so SSE stays GET-only; POSTs use `fetch`. Static HTML cannot carry the per-session CSRF token: inject `<meta name="ccsdk-csrf">` at serve time (outside script tags, so hashes stay valid) or add a GET session endpoint. Serve `_next/static/*` without a session like `/assets/*` (build output holds no machine facts); Next's client navigation data fetches carry the cookie and pass the door.

**G. Recommendation.** **Pages Router + `next build --webpack` static export**, served by the existing Bun server behind the unchanged door: `default-src 'none'; base-uri 'none'; connect-src 'self'; font-src 'self'; form-action 'self'; frame-ancestors 'none'; img-src 'self' data:; script-src 'self'; style-src 'self'` — no script hashes, no nonce, no `unsafe-inline`, and shadcn/caffeine/dashboard-01 work (chart 1080×250, range switch and row drag 0 new violations). Add the CSS fallbacks (sidebar vars, Recharts wrappers, Sonner CSS, scroll lock, Select viewport), keep zod out of the client, and accept the residual style-attribute console errors or get the owner's explicit yes for `style-src-attr 'unsafe-hashes'` plus build-time hashes (zero-error, proved). If App Router is required, keep `script-src 'self' 'sha256-…'` with a build-time hash manifest and a headless CSP test. Risks: Pages Router is not create-next-app's default and the block examples are App Router, so porting/future updates cost manual work [hunch: no deprecation announced]; `scripts/build.ts --check` currently fails any `plugin/dist` file not built from `src/`, so the export needs its own folder or a build-script rule; the dashboard grows the plugin by ~1.1M; the CSP header is ~3KB with all hashes [hunch: well under normal server limits].
