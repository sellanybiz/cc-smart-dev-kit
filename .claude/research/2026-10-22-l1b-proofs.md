# L1b: offline live proofs on Claude Code 2.1.308

Date: 2026-10-22
Status: input to L2's contract rows (`docs/claude-code-contract.md`), and to W2 and BR3

How: a fake Anthropic server on a free local port, a throwaway `HOME` and `CLAUDE_CONFIG_DIR`,
a fake API key, `--setting-sources ""`, `--strict-mcp-config`, a throwaway plugin with logging
hooks; nothing reached Anthropic or the person's config. The scripts and logs are in the lead's
job folder (`tmp/l1b/`), not in the repo.

1. **`onFailure: "block"` (PreToolUse command hook) [proved].** A hook that exits 1, times out,
   or cannot start blocks the call; the model reads the tool result `PreToolUse:Bash hook error:
   [<command>]: failed; blocking because onFailure is "block"` (or `timed out; blocking …`).
   Without the field the call runs. **Ignored on Stop**: the turn ends, with only a
   `stop-hook-error` notification.
2. **A background Agent's PostToolUse [proved].** `tool_response` holds `isAsync`, `status:
   "async_launched"`, `agentId`, `description`, `resolvedModel`, `prompt`, `outputFile`,
   `canReadOutputFile`, `canContinueAgent`. Order: PreToolUse, then PostToolUse and
   SubagentStart (they race), then SubagentStop, then Stop. In `-p`, an Agent call without
   `run_in_background` launched in the background; `false` had to be explicit.
3. **A Stop hook's `{"decision":"block","reason":…}` [proved].** The turn continues with
   `Stop hook feedback:\n<reason>`; the next Stop input has `stop_hook_active: true`; a hook that
   always blocks is overridden after 9 (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`); it shows as a
   `stop-hook-error` notification.
4. **A subagent at a 429 (P-BR2) [proved].**
   - Foreground: 11 requests over about 187 s; the parent's Agent result is an error `Agent
     terminated early due to an API error: API Error: Request rejected (429) · <message> …`;
     PostToolUseFailure and StopFailure (with `agent_id`, `error: "rate_limit"`); **no
     SubagentStop**.
   - Background: PostToolUse at launch, StopFailure later, no SubagentStop and no
     PostToolUseFailure; the parent gets a `task_notification` with `status: "failed"`.
   - With `CLAUDE_CODE_RETRY_WATCHDOG=1` (from `--settings` env), `max_retries` goes from 10 to
     300; it finished after the fake turned 200 at 90 s, and it outlasted a 240 s outage.
5. **The breaker's 429 [proved].** `retry-after: 30` with `x-should-retry: true`: retried 30 s
   apart (`system/api_retry` events); the end text is `API Error: Request rejected (429) · <the
   body's message>`, exit 1, `terminal_reason: "api_error"`.

Also: the 2.1.300 short-429 row's ending text is out of date under an API key on 2.1.308 (now
`Request rejected (429) · <message>`).
