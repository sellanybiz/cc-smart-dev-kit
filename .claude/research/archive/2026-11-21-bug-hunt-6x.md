## Edge-case hunter: what it found

### Critical

1. **An import cycle in the split.**
   - **Trigger:** `userAwayHook` moves to its own module and imports `guardCrash` from `../specs` (`specs.ts:79-88`, `:277-280`).
   - **Result:** `HOOKS` is built before `userAwayHook` is set. `user-away`'s PreToolUse runs with `onFailure: block`, so a load failure blocks the question tools.
   - **Why no test catches it:** test files import `./specs` first, and only three entries run as a subprocess (`src/testing/hooks.ts:140-152`).
   - **Test:** run every entry as a subprocess, and assert that the logged hook name matches.
2. **A status line runner that goes missing breaks the command that would fix it.** Causes:
   - the per-config-folder `stateDir`;
   - a `restore` run under another `CLAUDE_CONFIG_DIR`;
   - setup's write order (`setup.ts:323`);
   - Bun refusing a missing `--config=`.

   The plan dropped the runner because of this.
3. **`sideEffects: false` can change `router.js`.** "Same behaviour, tests green" does not check the router's bytes. The plan dropped `sideEffects` because of this.

### Warning

- **A size test that reads `plugin/dist` cannot go green in a builder's worktree:** builders never run `bun run build`. So it builds into a temp folder.
- **No test checks that an entry wires its own spec**, though `entries.test.ts` was claimed to.
- **The status line's two lookups read different folders:**
  - `alertsAt(paths, process.cwd(), …)` (`cli.ts:350`) runs before stdin is read;
  - `currentTask` reads `input.cwd` (`statusline.ts:177-183`).
- **`os.homedir()` ignores a changed `HOME`** in Bun. Probe: `{"before":"/home/user","afterSet":"/home/user"}`. `homeDir()` falls back to it (`src/gateway/paths.ts:30-33`), and `cliPaths({})` does too. Instances: `gateway/context.test.ts:79`, `hooks/fail-closed.test.ts:118`, `cli/paths.test.ts:24`.
- **The preload's folder:**
  - `removeTempDirs()` deletes every `tempDir` folder after each test (`temp.ts:8-17`);
  - `cleanGitEnv()` strips `CLAUDE_*` (`temp.ts:37-71`), so `CLAUDE_CONFIG_DIR` must be `<home>/.claude`.
- **The skills pass a bare base:** `pull-request/SKILL.md:55` and `commit/SKILL.md:78` give `--base <base>`, and `--base` wins as written. So the fix must resolve a bare name.
- **Removal already deletes a worktree's branch** (`scan.ts:934-945`, `:993-1016`; `command.ts:378-383`; `clean.ts:136-143`). What is missing is the branches with no worktree.
  - T-qic5ko asks for this on `--clean` and on the auto-clean, never a sweep of every branch.
  - The auto-clean shares `cleanWithStrays` (`auto-clean.ts:46`).
- **T-ktucun has two more parts:** a project's own WorktreeCreate hook, and macOS `ps` without `-A`/`-x` (`machine-facts.ts`).
- **`migrate` writes the launcher itself** (`migrate.ts:1306-1309`). This only matters for a runner.
- **What a runner must keep:** `argv[1]`, the `--no-env-file` check in `execArgv` (`jobs/commands.ts:192-196`), `browser check` reading `process.argv[1]` (`cli.ts:683`), and exit codes and signals.
- **Doctor has no runner check.** This only matters for a runner.
- **The shell reader:**
  - **PowerShell:** a glob or a brace means another thing there (`job-route.ts:540`).
  - **A tilde:** it changes `git -C ~/repo` routing (`job-route.ts:309`, though `change-dir.ts:73` already expands `~`), and `[ -d ~/x ] && bun test` as glue (`classify.ts:1377-1378`).
  - **The plan's wording was wrong:** `computed` comes from `isComputedWord` (`command.ts:1688-1693`), not from `filled`.
- **With no `origin` remote,** the gates' fetch hint is wrong.
- **Kit tasks stay on one machine**, unlike the files in git.

### Suggestion

- zod is about 250 KB, a high floor.
- A third copy of the install lookup (a runner).
- Delete only the tracked files, never `.claude/tasks/`: it is the default deploy-task folder (`deploy/files.ts:21`).

### Covered

- `run.ts` does not import `specs.ts`. Only tests read `GUARD_BUNDLES`.
- The macro runs at build time, and the port guard is preload-only.
- A branch checked out elsewhere is kept. A stale origin keeps branches. Squash merges go through the replay.
- `ASSIGNMENT` already reads `+=` (`command.ts:1284`), so only `GH_POINTING` lacks it.
- No code links to the `T-*.md` paths.
