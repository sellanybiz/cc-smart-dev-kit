# Bug hunt for 6.x: real bugs, lighter hooks, the old task files cleared (6.2.0)

## Summary

- Fix the bugs that still hold after 6.0:
  - tests that can write to the real home folder;
  - task listings read against a stale local `main`;
  - a generated Next.js file that keeps finished worktrees;
  - `[object Object]` in a task's history;
  - a parked-worktree flag passed the wrong way;
  - the worktree path built in nine places;
  - merged builder branches that are never deleted.
- Make every hook lighter (each loads every other hook today), measured before and after, and stop the status line reading git twice for two different folders.
- Clear the 27 old task files the kit stopped reading in 5.0: every item in them is fixed here, moved to a kit task, or recorded as moot. One pull request, release 6.2.0.

## Context

**What started it.** Plan 2 (#242) was queued in 2.x as "the bug hunt and guards". On 2026-11-21 the owner re-scoped it:
- "Bugs + speed + cleanup";
- the old task files: "Fold in, then delete all";
- the expert-agents proposal: "Drop it".

**What fell away.** 6.0.0 removed the guards, and 5.0.0 removed the code behind T-xscjki and T-gpmiae. So these old items are dropped:
- the guard items;
- the after-merge broadcast;
- the stop-guard research;
- the five-Bun dispatcher. A Bash call now starts two, and Claude Code runs an event's hooks in parallel.

**What the reviews changed.** The edge-case hunter and the senior engineer's plan read (both on `opus` at `xhigh`, 2026-11-21; reports archived with the plan) changed four things:
- the status line runner is dropped;
- the hook split is measured first;
- the test home fix replaces `os.homedir()`;
- the shell-reader change is dropped.

## Research

Three scouts read today's main (6.1.0), and the two reviews checked their claims against the code. The full findings: `.claude/research/archive/2026-11-21-bug-hunt-6x.md`.

**Tests and home (T-425mbb, T-rg3k7x)**
- The preload (`src/testing/setup.ts`) sets only `TZ` and the port guard.
- In Bun 1.4.4, `os.homedir()` keeps the real home after `process.env.HOME` changes (probed twice).
- `homeDir()` (`src/gateway/paths.ts:29-33`, in the router bundle) falls back to it, and so does `cliPaths({})` (`src/cli/paths.ts:118`).
- Children started with a hand-built env that has no `HOME` do the same: `migrate.test.ts:382`, `gateway-cli.test.ts:394`, `browser/launcher.test.ts:80`.
- `removeTempDirs()` runs after each test, so a preload folder cannot come from `tempDir()`. `cleanGitEnv()` strips `CLAUDE_*`.
- T-rg3k7x's link to the real home is a hunch: its test already has its own temp home (`gateway-cli.test.ts:151`). It is reproduced before it is fixed.

**Task listings**
- `task list --branch` and `--branches` read a bare base name as the local branch (`src/tasks/command.ts:364`, `src/tasks/deploy/branch.ts:99-100`, `:157-165`). The gates read `origin/<base>` (`command.ts:427-428`).
- The shipped skills pass a bare name (`plugin/skills/pull-request/SKILL.md:55`, `commit/SKILL.md:78`), so the fix must resolve a bare name, not only change the default.

**`next-env.d.ts`.** It is missing from `REBUILDABLE` (`src/hooks/local-files.ts:38-61`). It keeps five finished worktrees here, and the session-start note says the same (`worktree-leftovers.ts:174`).

**`[object Object]` (T-fx5swq)**
- The take-over records raw claim objects (`src/tasks/work/store.ts:958-967`), while `shape()` (`:60`) and the reclaim (`:1356`, `:1371`) record text. `shown()` (`src/tasks/work/history.ts:44-49`) prints them with `String()`.
- A claim has no "since" field (`types.ts:40-44`).

**Parked (T-cm3mrt).**
- `scan.ts:611`'s `parked` deliberately needs a branch (`verdict.ts:75`, `:179`, `:189`).
- The bug is at `scan.ts:646`: `contentsOf` gets that branch-gated value as its own-deletions flag. It should get the name-only test (`isParkedWorktree(path)`, as at `:874`).
- Merging the two tests would let a detached parked folder with unique commits be removed.

**The worktree path (T-ktucun)**

**Merged builder branches (T-qic5ko)**
- `removeWorktree` and a gone worktree already delete their branch (`scan.ts:934-945`, `:993-1021`, `command.ts:378-383`, `clean.ts:136-143`), through `workOnBase` (replay, cherry-pick, pull request).
- What is missing: the 44 merged `worktree-agent-*` branches with no worktree, which nothing lists.
- The auto-clean shares `cleanWithStrays` (`auto-clean.ts:46`) and runs from hooks on every machine.

**Hook cost**

| Bundle | Size | Run, measured |
|---|---|---|
| Every hook bundle | 583 KB | about 42-62 ms |
| `playwright-output.js` | 9.7 KB | 7 ms |
| `worktrees-clean.js` (no `specs.ts`, has zod) | 331 KB | 49 ms |
| A bare `bun` | | 4-6 ms |

- zod is about 180 KB of each bundle, reached through `run.ts:35` → `project/config.ts:3`.
- So the hook split alone saves perhaps a fifth. The floor is zod and the schemas built at load.
- `run.ts` never imports `specs.ts`; only tests read `GUARD_BUNDLES`. user-away's `onCrash` uses `guardCrash` (`specs.ts:79-88`): a split that leaves it in `specs.ts` makes an import cycle that throws at load.
- No test runs every entry as a subprocess; only three are (`src/testing/hooks.ts:140-152`).

**The status line**
- **Starting Bun:** the launcher starts Bun twice, about 6 ms of a tick of 100 ms or more. Loading the 2.2 MB `cli.js` is the cost.
- **Folders:** it reads git for two folders. `alertsAt(paths, process.cwd(), …)` (`src/entries/cli.ts:350`) runs before stdin is read. The task segment reads `input.cwd` (`statusline.ts:183`). The alerts follow the folder the process started in, not the session's.

**The old task files.** There are 27 in `.claude/tasks/` and `archive/`. Each item has its outcome in the table below (§ Approach 6).

**Other leftovers**
- **Crew:** the `crew_id` columns stay (a migration buys nothing). Two crew plans are not archived. The `crew-loop-stop` worktree and the `crew-job-load-limits` branch are left.
- **Queue limits not in `docs/jobs.md`:** a heavy command run outside the Bash tool (T-zujkvy), or inside `bash <(…)` or `ssh` (T-osnrxr).
- **`docs/roadmap.md:280-283`** still calls the worktree engine "not yet deleted".
- **`after-merge.ts:225`'s `GH_POINTING`** misses `+=`. `GH_POINTING_TEXT` at `:317` already catches the name, so this is a small fix.

## Approach

1. **Lighter hooks, measured.**
   - **Step 0:** build `run.ts` plus one hook into a temp folder with `scripts/build-entry.ts`, and time a run against today's. Write the numbers on the phase.
   - **Split:**
     - each hook spec goes into `src/hooks/specs/<name>.ts`;
     - `guardCrash` goes into its own module;
     - `specs.ts` keeps `HOOKS`, `NON_GUARD_PRE_TOOL_USE` and `GUARD_BUNDLES`, and re-exports every spec (17 test files and `src/cli/project-checks.ts:67` import from it);
     - each entry imports only its own spec module.
   - **No `"sideEffects": false`:** it could change `router.js`.
   - **New tests**, each building into a temp folder (never `plugin/dist`, which is the main session's):
     - every hook entry runs as a subprocess with junk input, exits 0 and logs its own hook name;
     - a size budget per hook bundle, set from the measured build.
   - **`router.js` must not change.**
   - If step 0 shows zod and the schemas still dominate, the phase says so in its report, and a follow-up kit task records the zod work. That is a separate plan, not this one.
2. **The status line reads one folder.**
   - Read stdin first, then use the session's folder (`input.cwd`) for both the alerts and the task segment. With no input (run by hand), use `process.cwd()`.
   - Locate that checkout once and pass it to both. `alertsAt` (`src/workflow/alerts.ts:42`) takes the located checkout.
   - Test a session whose `input.cwd` is a worktree with its own `workflow.alerts`, while the process runs in the main checkout.
   - Measure a tick before and after.
   - The launcher is not changed.
3. **Tests never touch the real home.**
   - **The temp home:** the preload makes one temp home per run with `mkdtemp`, outside `tempDir()`'s list, and removes it in its own `afterAll`. It sets `HOME` and `USERPROFILE` to it, `CLAUDE_CONFIG_DIR` to `<home>/.claude`, and `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME` under it, all before any test file loads.
   - **`os.homedir()`:** the preload also points it at the temp home, with Bun's `mock.module("node:os", …)`, which keeps every other export. So `homeDir()` and `cliPaths({})` land in the temp home with no change to `src/gateway/paths.ts`, and `router.js` stays the same.
   - **A guard:** `cliPaths` throws on an argument that is not an object, T-425mbb's second direction.
   - **Proof tests:** `cliPaths({}).home`, `cliPaths(process.env).home`, and a child started with an env without `HOME`, none of them the real home.
   - **Children:** test children get `HOME` through one env helper in `src/testing/`.
   - **T-rg3k7x:**
     - reproduce it first (the full-suite order, `--seed`) and save the failing order on the task;
     - fix the root cause, whatever it is;
     - if it does not reproduce in five full runs, record that on the task with the seeds and close it as not reproduced.
4. **Worktrees.**
   - **Generated file:** `next-env.d.ts` joins `REBUILDABLE`, at any depth.
   - **One home for the path:** a new module `src/worktrees/paths.ts` with `worktreesFolder(repoRoot)` and `worktreePath(repoRoot, name)`, used by all nine places. The regex in `subagent-worktree.ts` is built from the same folder name.
   - **Parked:** at `scan.ts:646`, `contentsOf` gets `isParkedWorktree(path)`. `facts.parked` stays as it is. Tests:
     - a detached parked folder with commits ahead of the base is kept;
     - one whose commits are on the base is removed;
     - a parked folder's own deletions are not counted as the person's.
   - **macOS `ps`** in `machine-facts.ts` uses `-A` (or `-x`), with a test of the argv (T-ktucun's second part).
   - **Branch sweep:** `worktrees --clean` (never `--remove <path>`, never the background auto-clean) also deletes local `worktree-agent-*` branches that no worktree checks out and whose work the base holds, through the existing `workOnBase` and `tryDeleteBranch`.
     - Any other branch name is never touched.
     - A branch with unique commits is kept, with its reason.
     - `--dry-run` lists them.
5. **Tasks.**
   - **The listing's base:** when the repo has an `origin` remote and `origin/<base>` exists, a bare base name (from `--base` or the default) reads `origin/<base>`. With no `origin` remote, it reads the local branch as today, and the line says so. A missing `origin/<base>` gives the gates' fetch hint. This covers the skills' bare `main`.
   - **The claim text:** one helper, `claimText()`, used by `shape`, the take-over and the reclaim. `shown()` also renders the claim objects already stored.
   - **`after-merge.ts`'s `GH_POINTING`** reads `+=`.
6. **Words and the old files (after the code merges).**
   - **Docs:**
     - `docs/jobs.md` § Limits names the two queue limits;
     - the roadmap's stale line goes;
     - CHANGELOG 6.2.0, with what to run: `cc-smart-dev-kit update`.
   - **Each code phase updates its own docs** in the same change:
     - `bundles`: `.claude/rules/hooks.md`, the `paths:` of `hooks-guards.md` (`src/hooks/specs/**`), the `.claude/CLAUDE.md` layout row and `docs/design/hooks.md`;
     - `worktrees`: the README `worktrees` row, the worktrees design page, and a `docs/claude-code-contract.md` row for the `worktree-agent-<id>` branch name (seen: 44 such branches here);
     - `tasks`: `README.md:595-596` and `docs/design/tasks.md:551`.
   - **The old task files:** the 27 tracked files are deleted, never the `.claude/tasks/` folder, which is the default deploy-task folder. Each item's outcome:

## Edge cases

- **An import cycle in the split.** `guardCrash` gets its own module. The every-entry subprocess test catches any cycle, with the built bundle, not only the source.
- **An entry that imports the wrong spec.** The same test asserts the logged hook name.
- **`router.js`.** No `sideEffects`, and `homeDir()` is not touched. `git diff --stat origin/main -- plugin/dist/router.js` is empty after the build.
- **The temp home.**
  - It outlives every test: own folder, removed in `afterAll`.
  - `CLAUDE_CONFIG_DIR` is `<home>/.claude`, so a child that loses `CLAUDE_*` to `cleanGitEnv` still lands there.
  - `mock.module("node:os")` keeps every other export, proved by a test.
- **A test that needs the real home.** None should. One that does is fixed at its cause.
- **The status line with no stdin** (run by hand) uses `process.cwd()`, as today.
- **A worktree whose alerts differ from the main checkout's** now shows its own. That is the intended change, and the CHANGELOG says so.
- **The branch sweep:**
  - only `worktree-agent-*`, only on `--clean`;
  - kept: a branch checked out anywhere (git refuses, and it is kept), a branch with unique commits, and every branch when the base cannot be read;
  - a branch a running builder still uses is checked out in its worktree, so it is kept.
- **The listing's base:**
  - no `origin` remote: local, as today, with a note;
  - `origin/<base>` not fetched: the gates' fetch hint;
  - a person's `--base origin/main` is read as written.
- **Deleting the old files:** only the tracked `T-*.md` files. The folder stays, and `oldTaskFiles` (`deploy/files.ts:121-127`) still counts any that remain elsewhere.
- **Kit tasks stay on this machine:** the moved items are local work tasks, not in git. The git history keeps the files.
- **Axes that cannot apply:** money, auth, schema and migrations (none), UI (the portal is untouched), concurrency (no new lock or shared state).

## What could break

- **Every hook entry** and the `hooks.json` checks (`entries.test.ts`, `matrix.test.ts`), the build, and `router.js`.
- **The status line's alerts** for a session in a worktree.
- **Any test that relied on the real home**, and the test children's env.
- **The worktree scan's consumers:** `worktrees`, `worktree-leftovers`, `herdr`, `sessions`, `propose`, `doctor --live`, and `subagent-worktree`.
- **`task list` readers:** the pull-request and commit skills, and the prod gate's hint.

## A simpler approach?

- **Hooks:** dropping `sideEffects` and the runner already took the cheaper path. The split is the smallest change that stops one hook loading the others. The zod floor needs its own plan, measured first.
- **Test home:** `mock.module` in the preload touches no shipped code. Changing `homeDir()` would change `router.js`.
- **Everything else** is a one-place fix.

## Rollback

A new version that reverts a phase. No managed user file changes in this plan, and no stored data changes shape. The claim text is read either way.
