# Slop homes 2: the second audit's seven copies go to their one home (6.7.2)

**Summary.** The second slop audit (`.claude/audits/2026-11-26-slop-homes-2.md`) confirmed seven
more copies of shared homes, in the code the first audit did not cover. Four are hand-edited JSON
files read with a plain `JSON.parse`, so a file saved with a byte order mark (BOM) breaks there.
This patch moves every copy onto its home and ships as 6.7.2.

Approved by the owner on 2026-11-26 ("Fix all 7 as 6.7.2"), with the router restart this costs.
Base: main at ebaf2a92.

## Goal

Each finding's code calls its one home. A BOM no longer breaks:

- `gateway.json`, which today turns every slot off after a router restart;
- a project's `.claude/settings*.json` in doctor, which today gives false warnings;
- `package.json` in the job classifier, which today judges a script by its name;
- `settings.json` in `migrate`, which today refuses a file the write accepts.

The three other copies keep their behaviour, apart from what the home adds: `windowsHide` on the
blocking gh calls, and `\r\n` handling for the worktree list.

## Decisions

- **The router bundle changes, on purpose** (finding 1). `src/gateway/config.ts` is in
  `plugin/dist/router.js`, so `parseUserJson` there changes it, and each machine's `gateway
  setup` restarts its router once on update. The owner accepted this when approving. The
  CHANGELOG says so.
- **A blocking gh runner gets its own zod-free home** (finding 5). It sits next to
  `src/hooks/git.ts`, because `after-merge` (a hook) must not import `merge-check.ts`, which loads
  zod. `merge-check.ts` re-exports what moved. `GH_TIMEOUT_MS` and the `ghMissing` test live there
  once.
- **`ListedWorktree` gains `bare`** (finding 6), so `project-state.ts` can drop its private parser.
- **`messageOf` moves to a dependency-free module at the top of `src/`** (finding 7), beside
  `path-compare.ts`. `gateway/config.ts` re-exports it, so its ~20 importers need not change in
  this patch. The private copies are deleted, and so is the unused `_reasonOf` in
  `portal/api/work.ts`.

## Edge cases

- **BOM, finding 1:** a broken `gateway.json` still throws `ConfigError` with today's text, which
  never quotes the file (it may hold a key). The router's watch keeps its last good config, as
  before.
- **BOM, finding 2:** a settings file that is not JSON still gives null, as Claude Code cannot run
  it either.
- **BOM, finding 3:** `job-route` already bundles `parseUserJson`, so the hook's size budget holds.
  `entries.test.ts` proves it.
- **The gh twin, finding 5:** a timeout, a missing gh and a non-zero exit answer as each caller
  answers today. after-merge stays zod-free (`entries.test.ts` traps it). A Windows run is not
  possible here: `windowsHide` is checked in the spawn options, as `runGh`'s own tests do.
- **Worktrees, finding 6:** a bare entry stays left out. `\r\n` output now parses. Restore's
  callers (`cli/restore.ts:343`) see the same paths.
- **messageOf, finding 7:** the same text for an `Error` and for any other thrown value. The hooks
  that import it stay zod-free.
- **The portal's `api/` folder:** another worktree has an unmerged commit there, in `types.ts`
  only. This plan touches `work.ts` alone, one deleted function, so a conflict is unlikely.

## What could break

`loadConfigFile`'s ~20 callers and the router's watch; doctor's project lines; the job
classifier; `migrate`'s pre-check; `worktrees clean` and `after-merge`'s gh calls; restore's
worktree files; everything that imports `messageOf`. Each builder runs its callers' tests.

## Simpler?

Only the four BOM readers: rejected by the owner, who chose all seven.

## Rollback

Revert the merge commit. No data, config or output shape changes. A rollback restarts the
router once more.

## How we prove it

- For each BOM reader, a test that fails on the old code with a BOM file.
- For the gh twin, a test of the spawn options (`windowsHide`) and of the three answers; for the
  worktree parser, a `\r\n` case and a bare entry.
- `bun run check`, both validates, `build:check`. `router.js` changes, and that is expected.
- Review: `/cc-smart-dev-kit:build` § 6's two review-split rounds at the normal tier, then a
  `cc-smart-dev-kit:senior-engineer` final review before push (the gate counts only that agent).
