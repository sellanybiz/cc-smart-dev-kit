# PM1 — claude-mem's model, key and fallback, set from the portal

**Goal.** The owner asked (2026-10-23): from the portal, point claude-mem at the OmniRoute gateway, change its model, add its API key, and set its fallback. Today the kit sets claude-mem only in `setup`, and only by following the scout slot's first `<backend>:<model>` target (`src/machine/claude-mem.ts`, its header); it never writes claude-mem's quota fallback (`CLAUDE_MEM_QUOTA_FALLBACK_*`, the owner's rule of 2026-10-17: no model of the plugin's own). The person choosing one in the portal is not the plugin choosing: it is the person's own value. UI/UX work (D50): opus.

## How to read
Read `src/machine/claude-mem.ts` whole (its header is the contract: the seven owned keys in `~/.claude-mem/settings.json`, the `unchosen` values, why a person's value is never taken back), then `.claude/rules/setup-and-managed-files.md` (§ Never take what is not ours, the `secret` key), `.claude/rules/portal.md`, `.claude/rules/gateway.md` § Settings and secrets. **claude-mem's own settings:** read what each key accepts from claude-mem's own source in the installed plugin folder (`~/.claude/plugins/cache/thedotmack/claude-mem/<version>/`, read only) and its docs — the provider values, the openai-compatible preset/base URL/model/key, the key pool (`CLAUDE_MEM_OPENAI_COMPAT_API_KEYS`), and the quota fallback's provider/model values; at least two sources, name them in your report. Then the portal's Machine page and its cards (`portal/src/views/machine.tsx`, `portal/src/components/machine-cards.tsx`), the actions (`src/portal/actions.ts`: how `slot.*` and the browser token's masked field save a value), and the model list the slot picker reads. Give wide reading to a scout subagent in the background, and keep only its conclusion.

## Build
1. **The fact:** a read-only answer of claude-mem's state (its route — Claude or a backend model —, its model, whether a key is set (never the key), its quota fallback, and where each value came from: claude-mem's own default, the scout slot through setup, or the person), from claude-mem's settings file and the kit's own records, through `src/portal/api/` (typed, mirrored in `portal/src/api/wire.ts`). claude-mem not installed or too old (`CLAUDE_MEM_MIN_VERSION`): the card says so with the fix.
2. **The writes,** as portal actions that run the kit's own code and ask first: the route and model (Claude, or a `<backend>:<model>` from the live list — the same list and check the slot picker uses, never a model typed free); the key (a masked field; saved through `applyManagedJson` with the key named `secret`, so the file stays mode 600 and no answer, log or error ever holds it; default: the gateway's own OmniRoute key, as setup uses today, with "use another key" as the choice); the quota fallback (provider and model from the same list, or none). Every write goes through `src/setup/` (backup, atomic write, lock) and is owned, so `restore` takes it out. After a person's write, `setup` must leave those keys as the person's (`claude-mem.ts`'s rule already: a value that is not the kit's is the person's) — prove it with a test that runs setup after a portal write.
3. **The card** on the Machine page: the state, the three controls, the source of each value, and the fallback line. The words say what leaves the machine: the summaries of every session go to the chosen backend.
4. **Docs:** README § The portal and the claude-mem part of setup, `docs/design.md` (claude-mem, and § The portal), `plugin/skills/gateway/SKILL.md` if it tells a person how to point claude-mem at a model.
