# PF1 — the portal's actions never block it, and its crew pages work from any folder

**Goal.** The 1.1.0 integration review (Opus, xhigh) found that four portal actions freeze the whole portal server, and that the crew pages and actions read the portal's own folder. Both must be right before 1.1.0 ships.

## How to read
Read `.claude/rules/portal.md` first (the door, actions run the CLI's own code, a page asks before it changes anything, never a blocking spawn in an action's path). Then open only the functions you need, by line range. Give reading beyond the files you edit to a scout subagent in the background, and keep only its conclusion. The pattern to copy for a CLI child: `src/portal/flow-read.ts` (B6e: `Bun.spawn` of the CLI's own command with both bun flags, the portal's HOME and CLAUDE_CONFIG_DIR, a timeout, shared and cached).

## The findings (the reviewer's evidence)
1. **Medium — four actions block the server.** `crew.stop`, `crew.resume`, `crew.rm` and `worktrees.clean` run `Bun.spawnSync` paths: `crewContext` passes `runProgram: realRunProgram` (`src/crew/claude.ts:61-63`); `runCrewStop`/`runCrewResume` call `callClaude(…, CLAUDE_END_TIMEOUT_MS)`, 30 s (`src/crew/end.ts:43`, `:109`, `:121-126`); `runCrewRm` uses `runGit` (sync, 30 s; `src/crew/remove.ts:102`, `src/hooks/git.ts:45`); `worktrees.clean` reaches `fetchBase` and more sync spawns (`src/worktrees/scan.ts:50`, `:163`, `src/worktrees/machine-facts.ts:279`, `:360`, `:378`). A click freezes every page, every other action and the live stream for up to 30 s per call. `docs/design.md` (about lines 919-927) lists these actions as non-blocking, so the doc is wrong too.
2. **Low, but it breaks the pages — the crew actions and pages read the portal's own folder.** The portal starts with `cwd: paths.home` (`src/entries/portal.ts:127`, `:148`). `crewContext.cwd = action.cwd` → `actOn` → `readRecords` → `locateCheckout(ctx.cwd)` refuses outside git (`src/crew/board.ts:79-85`); `/api/work` and `/api/crew/<id>` use the same folder (`src/portal/api/work.ts:113-123`). On a normal start the Work page shows no crew and no buttons. Verify this on a test world whose portal runs from a non-git home, then fix: the crew data is the machine's (`listAllCrew`), grouped by repository and lead, and a crew action resolves its record by id and acts in `record.repo`.
3. **Low — `crew.rm` and `crew.stop` do not refuse on the server without `confirm: true`** (`worktrees.clean` and `project.write` do). Add the same refusal.
4. **Low — the live stream's replay buffer** (`src/portal/live/hub.ts`): `ping`, `hello` and `reset` frames go into the shared buffer, so pings alone fill `BUFFER_MAX` (512) in about 16 minutes and a reconnect gets `reset` instead of a replay. Frame them without a buffer entry. And each stream's queue has no byte cap (`stream.write` never checks `controller.desiredSize`): close a stream whose queue falls past a bound.
5. **Low — the first poll after a portal start** (`src/portal/live/sources.ts`, `offsets.get(repo) ?? 0`, `guardOffset = 0`) publishes the whole crew history and guard log as live events. Seed each offset at the current file size without publishing, as `pollRouter` seeds `recent`.
6. **Low, tests only — the gateway's secrets test** (`src/cli/gateway-cli.test.ts:2754-2823`) never runs `gateway slot … custom` or `clear`. Add `slot opus custom`, `slot judge claude`, `slot judge custom`, `slot opus clear` to the planted-key run (`.claude/rules/gateway.md`: every command goes in it).
7. **Low — `crew lead tell`** (`src/crew/lead-tell.ts`): a store write failure on receiver 2 leaves receiver 1's note recorded with no `SendMessage` line printed. On failure, still print the lines for the receivers already recorded, and name the one that failed.

## Build
Fix 1 at the root: each of the four actions runs the CLI's own command (`crew stop|resume|rm <id>`, `worktrees --clean`) in a child process with `Bun.spawn`, the way `flow-read.ts` does, in the crew record's repository, its output collected into the action's result; or an async path through the existing async git (`runGitAsync`, `src/hooks/git.ts`) — pick one, say why. Never a `spawnSync` reachable from an action. Fix 2–7 as above. Docs: `docs/design.md` § The portal (the non-blocking paragraph, the Work page's data), `README.md` § The portal if a page's words change, `.claude/rules/portal.md` only if a rule's words must change.
